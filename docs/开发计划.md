# CodeCounter 开发计划

> 本文档记录经确认的开发计划，是后续开发与验收的基准。计划如有变更，
> 应先修改本文档再动代码。

## 一、项目定位

一个 **Windows 原生**（Win32 控件、非 WebView）的代码行数统计小工具：

- 默认统计**启动时的工作目录**
- 可切换统计目录，也可只统计**指定的若干文件**
- 自动跳过 `node_modules`、`.idea` 等冗余目录，规则可自定义
- 结果以**排行榜 + 条形图 + 语言图标**直观展示
- 界面风格对齐 Win32 标签页设置窗口（选项卡 + 复选框 + 分组框）

## 三、技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Go 1.25+ | 编译为原生可执行文件，便于跨平台构建 |
| GUI | `lxn/walk` | 直接使用系统 Win32 控件，天然具备目标界面风格 |
| 计数引擎 | `github.com/boyter/scc` | 语言识别准确，可区分代码 / 注释 / 空行，性能好 |
| 条形图 | `walk.CustomWidget` + GDI 自绘 | walk 无图表控件，自绘可保持原生观感 |
| 语言图标 | 内置 PNG 资源 | walk 不渲染 SVG，需转为 PNG |
| 配置 | JSON，位于 `%APPDATA%\CodeCounter\` | 便于用户查看与重置 |
| 打包 | GoReleaser + `go-winres` | 版本注入、图标、清单、高 DPI 一站式处理 |

**边界说明**：`lxn/walk` 仅支持 Windows，因此本项目为 Windows 专用程序，
CI 只构建 Windows 目标（`amd64` / `arm64`），不产出 Linux / macOS 版本。

### 设置对话框

标签页：`通用` / `排除规则` / `显示` / `关于`

- **通用**：默认目录策略（启动工作目录 / 上次使用 / 固定路径）、开机自启、界面语言
- **排除规则**：内置名单开关、自定义规则文本框（支持 glob，一行一条）、` .gitignore` 开关
- **显示**：主题、条形图条目上限、是否显示语言图标
- **关于**：版本号、构建信息、许可证

底部：配置文件路径 + `[打开所在文件夹]` + `[重置默认]`

## 六、功能分期

| 阶段 | 分支 | 内容 |
| --- | --- | --- |
| P0 | main / dev | 仓库初始化、工程配置、目录骨架、CLI 骨架 |
| P1 | dev | 计数引擎、排除规则、单元测试（含 CLI 模式便于验证） |
| P2 | dev | 原生主窗口、排行榜、自绘条形图、语言图标 |
| P3 | dev | 设置对话框、目录与文件选择、配置持久化 |
| P4 | dev | 应用图标、清单、无控制台、高 DPI、单实例 |
| P5 | dev | CI（含敏感信息扫描）、Release 工作流、GoReleaser |
| P6 | dev → main | 文档收尾、CHANGELOG、整体验收、打 tag 发布 |

## 七、分支与提交约定

- `main` 为发布分支，只接受 `dev` 的合并提交
- `dev` 为开发分支，所有开发在此进行
- 合并使用 `--no-ff` 并签名，保留里程碑
- 提交使用中文语义化信息，正文写清做了什么、为什么、影响范围、验证方式
- 所有提交与标签均使用 GPG 签名

## 八、CI/CD 设计

- **ci.yml**（push 到 `dev` / `main`，以及指向二者的 PR）
  - `go vet`、`go test ./...`、`golangci-lint`
  - Windows 构建矩阵校验
  - 敏感信息扫描（gitleaks），防止公开仓库泄露密钥
- **release.yml**（仅 tag `v*` 触发）
  1. 校验 tag 是否符合 `vX.Y.Z`（允许 `v0.1.0-beta.1` 这类预发布）
  2. 运行完整测试
  3. GoReleaser 构建 `windows/amd64` 与 `windows/arm64`
  4. 产出 zip 包、`checksums.txt`、自动生成变更记录
  5. 创建 GitHub Release（预发布 tag 自动标记为 pre-release）

版本号通过 ldflags 注入 `main.version` / `main.commit` / `main.date`。

## 九、验收标准

1. 计数结果与 `scc` CLI 对同一目录的抽样结果一致
2. `node_modules`、`.idea`、`vendor`、`dist` 等默认不统计，自定义规则生效
3. 排行榜、条形图、语言图标三者数据一致
4. 默认目录为启动时工作目录，且行为在文档中说明清楚
5. 可选择目录统计，也可选择文件统计
6. 设置可保存，重启后生效
7. 无控制台窗口、任务栏图标正常、高 DPI 下不模糊
8. PR 上 CI 通过；打 `v0.0.1` 之类的 tag 能自动产出可下载的 Release

## 十、公开仓库约束

- 从初始提交起即维护 `.gitignore`，覆盖构建产物、本地配置、密钥与日志
- 源码与文档中不出现本机隐私信息，示例路径统一使用占位值
- CI 中执行敏感信息扫描
- 提交前执行 `CONTRIBUTING.md` 中的隐私自查清单
