# 发布流程

本文档说明如何把 `dev` 上的成果发布为 GitHub Release。

## 一、发布前检查

1. 确认 `dev` 分支工作区干净、CI 全部通过

   ```powershell
   git switch dev
   git status --short
   ```

2. 确认 `CHANGELOG.md` 已更新到本次版本
3. 确认版本号符合语义化版本，例如 `v0.1.0` 或 `v0.1.0-beta.1`

## 二、合并到 main

```powershell
git switch dev
git switch main
git merge --no-ff -S dev
git push origin main
git switch dev
```

`main` 只接受来自 `dev` 的合并提交。

## 三、打标签并推送

标签必须使用 GPG 签名：

```powershell
git switch main
git pull --ff-only
git tag -s v0.1.0 -m "CodeCounter v0.1.0"
git push origin v0.1.0
```

标签格式会被发布工作流校验，不符合 `vX.Y.Z`（允许 `vX.Y.Z-预发布`）会直接失败。

## 四、自动构建与发布

推送标签后会触发 `.github/workflows/release.yml`：

1. 校验标签格式
2. 运行全部单元测试
3. GoReleaser 构建 `windows/amd64` 与 `windows/arm64`
4. 生成 zip 包与 `checksums.txt`
5. 按提交信息生成变更记录
6. 创建 GitHub Release；预发布标签会自动标记为 pre-release

可在 Actions 页面查看进度，产物在 Release 页面下载。

## 五、发布后验证

1. 下载 `codecounter_<版本>_windows_amd64.zip` 并解压
2. 确认压缩包内包含 `codecounter.exe`、`README.md`、`LICENSE`、`NOTICE`
3. 运行 `codecounter.exe --version`，确认版本号与标签一致
4. 运行界面，确认图标与语言 logo 正常

## 六、本地预演

不推标签也可以本地验证发布产物：

```powershell
goreleaser release --snapshot --clean --skip=publish
```

产物位于 `dist/` 目录（已被 `.gitignore` 忽略）。

## 七、回滚

若发布出现问题：

1. 在 GitHub 上把对应 Release 标记为 pre-release 或删除
2. 修复后发布新的补丁版本，不要复用已经推送过的标签
3. 如需删除标签，必须同时在本地与远端删除，并通知使用者
